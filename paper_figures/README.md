# Paper figures

The four figures actually embedded in the published paper, plus the tools
that generate them. File names below are historical (they don't match the
paper's own Fig. 1-4 numbering) — the mapping is spelled out in the table.

| Paper figure | File | Generator |
|---|---|---|
| Fig. 1 (pipeline diagram) | `pipeline_overview.pdf` | static asset, exported from `pipeline_v2_overview.svg` / `pipeline_v2_fig1_fusion.svg` (not script-generated) |
| Fig. 2 (per-class F1 by camera direction, 3 fusion strategies) | `fig4_fusion_by_direction_color.png` / `.pdf` | `regenerate_fig3_fig4.py` |
| Fig. 3 (class distribution by camera direction) | `dataset_class_distribution_trainval_color.png` / `.pdf` | `regenerate_class_distribution.py` |
| Fig. 4 (FF + shuffle correction: blind/classifier/oracle) | `fig3_shuffle_overall_color.png` / `.pdf` | `regenerate_fig3_fig4.py` |

Grayscale variants (`*_grayscale.png/.pdf`) are also generated for
print-safety but are not the ones embedded in the paper.

`captions.txt` holds the exact captions as printed in the paper.

## Regenerating Fig. 2 and Fig. 4 (`regenerate_fig3_fig4.py`)

`python3 regenerate_fig3_fig4.py` reads `figure_metrics_correct.json` from
this folder and draws both figures. Requires `matplotlib`, `numpy`. No
GPU / Kaggle needed.

`figure_metrics_correct.json` is a hand-verified data file and is not
regenerated by any script in this repo. If the underlying eval numbers ever
change, it needs to be re-verified and updated by hand.

## Regenerating Fig. 3 (`regenerate_class_distribution.py`)

`python3 regenerate_class_distribution.py`. The per-direction, per-class
sample counts are hardcoded in the script (see the module docstring for
provenance) rather than read from a JSON file.

Both scripts write PNG+PDF copies to this folder **and** to the repo root.

## `paper_figure_metrics.py`

Root-level module imported by `figures-creation.ipynb`'s metrics-export
cell to serialize evaluation results to JSON. Required by the notebook —
don't delete it.

`workspace_output/` is a separate, intentional archive of a full past
pipeline run (per the top-level README) and is left untouched — it's a
historical record, not part of the current figure-generation tooling.
